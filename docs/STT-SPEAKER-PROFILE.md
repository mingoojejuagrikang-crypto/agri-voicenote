# 화자 프로필 — 앱이 무엇을 모으고, 어디에 남기며, 무엇에 쓰는가

> v0.51.1 R6 (2026-09-02) · 사용자 고지용. 코드 진입점: `src/lib/sttConfusionCore.ts`(규칙) ·
> `sttProfileStore.ts`(저장) · `sttCorrectionTracker.ts`(수집) · `sttConfusionRuntime.ts`(확인 질문) ·
> `scripts/stt-confusion-build.mjs`(전역 표 생성).

## 왜

같은 숫자라도 사람마다 발음이 다르고, 음성 인식은 그 차이를 다르게 틀린다. 2026-09-02 실사용 5세션에서
「칠」이 「일」로, 「팔」이 「일」로 들려 그대로 기록될 뻔한 값이 오커밋 64건 중 8→1 8회 · 7→1 6회 · 7→3 5회였고,
「점」이 「삼」/「공공」으로 전사돼 자릿수가 바뀐 값이 30여 건이었다. 앱은 **어느 값이 어떻게 틀리는지를 사람별로
세어 두었다가**, 같은 형상이 다시 들리면 **값을 바꾸지 않고 한 번 되묻는다**(민구 결정: 자동 변경 없음).

## 무엇을 모으나

| 항목 | 내용 | 어디에 |
|---|---|---|
| 화자 id | 로그인 계정 이메일의 SHA-256 앞 8자(hex). **이메일 원문은 아니다.** 미로그인이면 `anon` | 세션 시작 로그 `meta.speaker` · `device.json`의 `speakerId` · 프로필 |
| 정정 쌍 | 값이 **정정되는 순간** 1건: 들린(파싱된) 값 → 최종값, 정정 경로(재녹음·직접값·터치·재질문·확인 질문), 그 값을 만든 STT 원문(24자까지)·신뢰도·alt 순번 | 로그 이벤트 `stt_correction:…`(`events.json`) |
| 혼동 후보 발동 | 후보가 생겼을 때 1건: 들린 값·후보·규칙·물었는지·사용자가 무엇을 골랐는지 | 로그 이벤트 `stt_confusion_hint:…` |
| 화자 프로필 | (화자, 마이크 종류)별 혼동표 — 「x로 들렸는데 y라고 말했다」 횟수와 분모, 「점」 소실 형상 횟수, 「첫째」(들린 값이 맞았다) 횟수 | 기기 IndexedDB `kv` 스토어 `__stt_profiles__` · export zip의 `stt-profile.json` |

모으지 **않는** 것: 이메일 원문·이름은 프로필·이벤트에 싣지 않는다(이메일은 종전대로 `device.json`에만).
음성 원문은 `stt_correction`의 `text`에 최대 24자만(기존 `stt` 이벤트가 이미 싣는 범위 안).

## 어디에 남나

- **기기 안**: 프로필은 세션 경계와 무관하게 누적되고 앱을 삭제하기 전까지 남는다(다른 사람이 같은 기기에서
  로그인하면 그 사람의 프로필이 따로 생긴다 — 키가 `(화자, 마이크 종류)`다).
- **로그 zip**: 「로그 내보내기」·동기화 후 자동 업로드 zip에 `stt-profile.json`(기기 전체 프로필 · 프로필이 0개여도
  파일은 있다)이 동봉된다. 회차마다 운영이 이 파일들을 모아 **전역 표**(`src/data/stt-confusion-default.json`)를
  갱신한다 — 새 사용자는 자기 프로필이 쌓이기 전까지 전역 표를 쓴다.

## 무엇에 쓰나 — 확인 질문

1. 값이 파싱돼 **셀에 커밋된 직후**, 프로필(없으면 전역 표)에서 「이렇게 들린 값이 실제로는 다른 값이었던」
   확률이 충분히 높은 후보를 찾는다(자리 치환·「점」 소실). 지지수 3건 이상 · 확률 15% 이상 · 들린 값 자체가 맞았을
   확률의 절반 이상일 때만 후보다. 🔴 **여기에 세션 안의 다른 값·범위는 쓰지 않는다**(민구 결정 09-02: 값 범위는
   사용자가 설정하는 이상치 알람의 몫 — 이 기능은 「발음 혼동 확률」만 말한다).
2. 후보가 있으면 값을 읽어주는 대신 **「1.7인가요, 8.7인가요?」**처럼 되묻는다(원값이 항상 첫째 · 후보 최대 2개).
   - 「첫째 / 네 / 확인」 → 들린 값 그대로 진행. 그 규칙의 분모가 올라가 **다음부터 덜 묻는다**.
   - 「둘째 / 셋째」 → 그 후보로 고쳐 기록한다(정정 쌍이 남고 프로필이 배운다).
   - 값을 다시 말하면 그 값으로, 「아니오 / 수정」이면 같은 항목을 다시 듣는다.
   - 「다음」 같은 이동 명령은 답하기 전엔 「먼저 답해 주세요.」로 거부한다. 종료·일시정지는 질문을 접고 수행한다.
3. 같은 셀에는 한 번만, 한 세션에 최대 30번만 묻는다. 이상치 알람이 같은 값에 떴으면 알람이 우선이고 질문은 없다.

## 운영 — 전역 표 갱신

```bash
node scripts/stt-confusion-build.mjs <growth-log 폴더…> --out src/data/stt-confusion-default.json \
  [--truth=audit --audit <sid\trow\tcolId\ttruth TSV>]     # 감사 전사가 있으면 최종값 대신 전사를 정답으로
node scripts/stt-confusion-sim.mjs <growth-log 폴더…> --mode loso [--sweep] [--detail]   # 발동·포착·위양성
```
